# Audit: use of the in-game scripting API (key `api_fidelity`)

Scope: every Programmable Block API member and every terminal property / action string used by `scripts/*.cs` and the shared blocks `tools/*_block.cs`, compared with the real in-game API, plus the stand-in `stubs.cs` that the scripts compile against and the sim implements. Read-only audit, 2026-10-13. No simulation was run (CLAUDE.md seed rule not triggered).

## 0. Method and evidence

The scripts reference the API only through `stubs.cs` (compile_check) so the question is "is each stub member real, and does the script use it as the game does". Steps: (1) grep of all `GetValue/SetValue/GetProperty/ApplyAction/GetActionWithName` string literals and of every `IMy*` type and `.Member` used; (2) page-by-page comparison with the Keen ModAPI doc mirror; (3) the sensors/IGC/AI audit (`sensors_igc_ai.md`) for Keen source facts.

| Tag | Source | Weight |
|---|---|---|
| [API] | Keen ModAPI doc mirror `keensoftwarehouse.github.io/SpaceEngineersModAPI/api/...` (IMyUserControllableGun, IMyLargeTurretBase, IMyTurretControlBlock, IMyCameraBlock, IMyShipController, IMyThrust, IMyGyro, IMyBatteryBlock, IMySensorBlock, IMyProjector, IMyWarhead, IMyShipMergeBlock, IMyShipWelder, IMyCubeGrid, IMySlimBlock, IMyIntergridCommunicationSystem, IMyTextSurface, IMyProgrammableBlock, IMyGridTerminalSystem, IMyRadioAntenna, IMyGridProgramRuntimeInfo, IMyFlightMovementBlock, IMyOffensiveCombatBlock, IMyOffensiveCombatStayAtRange, IMyTimerBlock, MyDetectedEntityInfo, MyIni, MyIniValue, TransmissionDistance, IMyBroadcastListener, IMyTerminalBlock) | high for names/types/units where the page states them; the pages do not state gyro units, MyIni case rules or boolean text |

## 4. Whitelist and language notes

* `System.DateTime.*`, `System.Exception.*` (including `StackTrace`), `System.Globalization.*`, `System.Text.*` are allowed [wiki].
* `System.Type` has only a short member list (`FullName`, `ToString()`, ...): `GetType().Name` is the only construct found that is probably outside it (A-1). `is`/`as` type tests (e.g. `tu is IMyLargeMissileTurret`) are not affected.
* No script uses reflection, `System.IO`, `Task`, `Thread`, `Console`, `Environment`, LINQ queries over blocks beyond what compiles in `compile_check`.

## 5. What changes items 5 and 9

* Item 5: use `TriggerDelay` (float seconds, namespace `SpaceEngineers.Game.ModAPI.Ingame`) for the timer; `UpdateTargetInterval` is `int`; model `IMyOffensiveCombatStayAtRange` as the attack-pattern component returned by `TryGetSelectedAttackPattern`; add `IMyUserControllableGun.Shoot` next to `ShootOnce()`; `FlightMode`, `OffensiveCombatTargetPriority`, `IMyAutopilotWaypoint` and `IMyAttackPatternComponent` are needed as types; `IsAutoPilotEnabled` stays get-only; the stub's `ApplyAction` should throw for an unknown action; compare names with the doc mirror, not only with memory.
* Item 9a confirmed (world vs camera-local direction); 9i confirmed (`ShootOnce()` exists); 9j: only the success check by `IsAutoPilotEnabled` is supported, `SpeedLimit` unit unverified; add a whitelist check for `GetType().Name` (A-1) to item 9 or the compile_check line of item 5.
