# Hull builder (`tools/hulls.py`)

Key `hull_builder`. A procedural hull generator on top of `tools/sebp.py`: describe a ship as voxel volumes (build half, mirror), let the
mapper turn the solid into real armour blocks, and get a refusal instead of a wrong block when something does not meet the hull.
Implements the rule set of `docs/design/systems_catalogue.md` section 6.3 and its work-list items (c) the semantic mount-face check and
(d) a hull generator. Files: `tools/hulls.py` (module), `tools/tests/test_hulls.py` (35 tests), `tools/hull_demo.py` (two demo hulls,
renders, timing). Python 3 only, no packages beyond the standard library (PIL is used by the demo only, as `sebp.thumb` already does).
No real ship is defined here; `sebp.py` and every existing design are untouched (Hornet/Gnat XML re-built and compared byte for byte).

## 1. Conventions

- Cells are sebp grid cells: `x` = Right, `y` = Up, `z` = Backward, **the bow points to -z**. A cell `(x, y, z)` is the block whose `Min` is that cell.
- Boxes are half-open `[lo, hi)`. Planes and float shapes use cell-edge coordinates (cell `i` spans `[i, i+1)`): `mirror('x', 0)` reflects about the
  boundary between cells -1 and 0 (even widths), `mirror('x', 0.5)` about the middle of cell 0 (odd widths).
- Directions are accepted as sebp names (`'Up'`, `'Forward'`), as `'+y'`/`'-z'`, or as vectors.
- Every block name the module can emit is generated by `subtype(kind, grid, heavy)` and asserted at import to exist in `defs.json`, be non-DLC,
  be on the right grid size and be 1x1x1 (both grids, light and heavy; `Prototech` never appears).

## 2. Quick use

```python
import sys; sys.path.insert(0, 'tools')
import sebp, hulls as H
from hulls import Volume, Zone, Zones

nose  = H.nose_cone('z', base=10, length=10, center=(0.0, 3.0), half=(3, 3), tip_half=(1, .8), shape='octagon')
body  = Volume.loft('z', 10, 24, (-3, 3, 0, 6), (-3, 3, 0, 6)).chamfer('z', 1)
wing  = H.swept_wing((3, 1, 12), 11, 11, tip_chord=4, sweep=0.8, thick=2, tip_thick=2)       # one side ...
solid = (nose | body | wing.mirror('x', 0)).largest_component()                            # ... mirrored
shell = solid.hollow(1, bulkhead_every=6, deck_every=3)                                     # 1-cell skin + partitions
bp    = sebp.Blueprint('Demo', 'Small')
res   = H.build_hull(bp, solid, fill=shell, reserved={'cockpit': Volume.box((-1, 6, 12), (2, 9, 15))}, skin_around=['cockpit'],
                     zones=Zones(Zone('bow', H.region(z=(None, 12)), heavy=True, color=H.ORANGE), default_color=H.hsv_mask(215, .25, .42)),
                     windows=H.region(y=(7, None), z=(9, 15)))
res.check(); bp.validate()                       # mount-face check + sebp (overlap, attachment, one piece, DLC)
print(H.format_report(H.report(bp)))             # blocks by type, mass, HP, PCU, bbox in metres
```
Then add systems into the reserved cells with `bp.add(...)` (cockpit, thrusters, guns) and `bp.write(...)` as usual.

## 3. `Volume` (integer cell sets, pure python)

Every method returns a new `Volume`; operands are never modified. `|`, `&`, `-`, `^` are union/intersection/difference/xor.

| group | API |
|---|---|
| primitives | `Volume.box(lo, hi)`, `wedge(lo, hi, face, toward, run=1)` (slanted face on any of the 6 sides, descending toward any perpendicular direction; `run`=cells per 1 cell drop: 1 = 45 deg, 2 = Slope2 ramp, `None` = proportional), `loft(axis, start, stop, rect0, rect1, shape)` / `frustum` (taper between two rectangles, `shape` = rect, ellipse, diamond, octagon), `ellipsoid(center, radii)`, `cylinder(axis, start, stop, center, radii, radii_end=None)` (cone when `radii_end` given), `prism(poly, axis, start, stop)` / `extrude` (2D polygon profile along an axis), `from_function(lo, hi, f)` |
| cuts | `chamfer(axis, n, corners)` (bevel the bbox edges parallel to an axis), `cut(point, normal)` (half space), `clip(x=, y=, z=)` |
| transforms | `translated`, `rotated(axis, k, about)`, `reflected(axis, at)`, `mirror(axis, at)` (union with the mirror image), `half(axis, at, side)`, `symmetry_error(axis, at)` (0 = symmetric) |
| hollow | `hollow(wall=1, bulkhead_every=K, deck_every=K, keel_every=K, thickness=1)`: N-cell skin plus planar partitions every K cells (z, y, x normals) so the hull stays one piece and keeps mass; raises `HullError` if hollowing splits a connected solid (a second pass keeps thin necks that only touch the outside diagonally) |
| queries | `bbox()`, `size()`, `exposed()` (cell -> exposed face directions), `surface()`, `erode(n, mode)`, `dilate(n, mode='face'/'edge'/'box')`, `depth_layers()`, `components()`, `is_connected()`, `largest_component()` |

## 4. Solid -> blocks: `build_hull(bp, envelope, ...)`

Returns a `HullResult` (`.blocks`, `.cell_block`, `.cell_kind`, `.exposure`, `.counts`, `.check()`, `.validate()`, `.report()`).

Inputs: `envelope` = the outer solid (exposure is decided against it, never against a hollowed interior); `fill` = the cells that get blocks (a
shell, default the envelope); `reserved` = `{name: cells}` the caller fills with systems; `clear` = cells that must stay empty (exhaust, muzzle; also
registered in `bp.reserve`); `skin_around` = names of reserved volumes that keep a one-cell armour skin (edges included) even inside a hollow hull;
`zones`; `slope2`, `slope2_sides`; `fillets`; `windows`; `flat`; `round_edges`; `check`; `require_connected`.

Exposed faces `E` of a cell (a face is exposed when the neighbour is neither in the envelope nor reserved), after dropping directions the zone/`flat` marks as hard:

| `E` | block | orientation |
|---|---|---|
| 0 or 1 faces | `Block` | `Forward`/`Up` |
| 2 perpendicular (an edge) | `Slope` (or `RoundSlope`) | the orientation whose zero-mount faces are exactly `E` |
| 3 mutually perpendicular (a vertex) | `Corner` (or `RoundCorner`) | same |
| opposite faces, or 4+ | `Block` | any |
| a staircase step: top cell `{a, r}` whose upstream neighbour (`-r`) shows only `{a}`, with the next column exactly one lower | `Slope2Base` + `Slope2Tip` | `Up` = `a`, `Forward` = `-r`; base wants full front + bottom, tip wants the half-height strip toward the base + full bottom |
| slope cell inside a `windows` area | `Window1x1Slope` | zero-mount faces exactly `E` |
| block cell with one exposed face inside a `windows` area | `Window1x1Flat` | open (zero-mount) face = the exposed face |
| `fillets=True`: empty cell with 2 perpendicular solid neighbours whose inner edge is solid | `Slope` seated on two cubes | open faces = away from both solids |
| `fillets=True`: empty cell with 3 mutually perpendicular solid neighbours | `CornerInv` | full faces toward the three solids |

Orientation is never tabulated: `orient_areas()` computes, from `sebp.mount_rects` for each of the 24 `(Forward, Up)` pairs, the mount area per grid
direction of every shape, and `pick_orientation()` takes the orientation whose zero-mount faces are exactly the faces that must look at space and whose
other areas are closest to the wanted ones. So the conventions are those of this repo's `sebp` by construction (catalogue 6.2). When no orientation fits, it
raises `HullError` rather than emitting the block. Light/heavy subtypes have identical mounts, so zones may mix them freely.

**Zones.** `Zones(Zone(...), ..., heavy_depth=None, default_heavy=False, default_color=...)`. A `Zone(name, where, heavy, color, flat, round, kind)` is a
layer: for each cell the first matching zone that sets an attribute wins that attribute, so stripes and markings go before the base livery. `where` is `None`,
a `Volume`/set, or a predicate; helpers `region(x=, y=, z=)`, `stripe(axis, period, width, offset)`, `any_of`, `all_of`. `color` can be a function of the cell
(panel lines, checkers). `heavy_depth=n` makes the outer n layers heavy and the inside light. `flat=('Down',)` ignores exposure of those directions (flat belly,
hard edges). `kind` is the `sebp` block kind tag the thumbnail palette keys on. Colours are `ColorMaskHSV` triples; `hsv_mask(h_deg, s, v)` converts normal HSV
(offsets 0.8 / 0.55, consistent with the repo palette: `DARK = (0, -0.81, -0.55)` is black, `(0, -0.8, -0.3)` a dark grey).

**Reserved cells.** Never armoured. They count as solid for their neighbours' shapes, so a roof cube under a turret or a stern cube in front of a thruster
keeps a full face toward it. `skin_around` adds the ring `dilate(volume, 1, 'edge')` inside the envelope, so a hangar floating in a hollow hull stays enclosed.
If the skin and the shell are not connected the builder refuses (`require_connected`): add a strut.

## 5. The "mount faces hull" check

`check_mount_faces(bp, support, flush=None, blocks=None)` (also `HullResult.check()`, run by `build_hull` unless `check=False`) is the semantic test
`sebp.validate()` cannot do. For every shaped 1x1x1 CubeBlock (plain cubes are exempt) it takes the block's own mount faces from `sebp.mount_rects` and the hull
`support` (envelope + reserved cells):

- **A.** every full-area mount face must look at a support cell (or at a direction the designer chose to leave flat, `flush[cell]`);
- **B.** every face with no mount at all (the slanted/open faces) must look at empty space, never at a support cell.

Negative test (`MountCheckTests.test_negative_wrong_orientation_is_refused`): all 24 orientations of a slope in the catalogue's wedge hull are tried. Every
orientation whose open faces differ from the exposed faces is refused with `HullError`, and the test asserts that at least one of them still **passes
`sebp.Blueprint.validate()`** (it touches a neighbour), which is the hole this check closes. A wrong corner is refused too. Not covered by A/B: a block turned
about the axis between two equal-looking solutions (Slope2Tip vs a 90 degree rotation); the mapper avoids this by scoring areas, and a test pins Base and Tip to
the same orientation.

## 6. Style helpers

| helper | notes |
|---|---|
| `nose_cone(axis, base, length, center, half, sign=-1, tip_half, tip_shift, shape)` | wedge/chisel (`rect`), cone (`ellipse`), `diamond`, `octagon`; `tip_shift` droops or raises the tip |
| `swept_wing(root, span, chord, tip_chord, sweep, thick, tip_thick, lift, span_dir, chord_dir, section, thick_center)` | wings, canards, fins (span along `+y`); sections `slab`, `wedge`, `diamond`; thin plates become slopes at the edges by the normal rules; build one side and `.mirror()` |
| `nacelle(center, start, length, radius, axis, sign, rear_taper, intake_taper)` | `Nacelle(.volume, .aft_cells, .exhaust_dir, .nozzle)`; `.nozzle` = the cell behind the exhaust end where a thruster goes |
| `spine(z0, z1, y_base, height, width, x_at, profile, ventral)` | dorsal/ventral spines: `blade`, `ramp`, `dome` |
| `stepped_deck(lo, hi, steps, inset, rise)` | bridge/superstructure pyramid; the step edges become slopes/windows |
| `hardpoints(volume, normals, footprint, height, margin, spacing, where, avoid, mirror, pairs)` | surface sites with outward normals on flat hull (each base cell exposes exactly the normal, so it stays a cube), symmetric pairs with `.mirror`; `Hardpoint.cells`, `.column(h)` for `reserved=` |
| `greeble(res, kind='panel'/'slab', pattern='scatter'/'grid'/'lines', ...)` | thin `ArmorPanel` or `HalfArmorBlock` slab in the free cell outside single-face cubes, deterministic by `seed`, never on reserved/occupied cells; checked with the same mount check |
| windows | `windows=` of `build_hull` (predicate/Volume/list): `Window1x1Slope` on slope cells, `Window1x1Flat` on single-face cells; a window with no attached neighbour reverts to armour |

## 7. Report and speed

`report(bp)` -> dict (`blocks`, `by_subtype`, `mass_kg` from `defs_stats.json`, `hp` = sum of component integrity, `pcu`, `bbox_cells`, `bbox_m`); `format_report(rep)` prints it.
`fast_validate(bp)` / `fast_attachment(bp)` give the same answer as `sebp.Blueprint.validate()` / `.attachment()` (tested equal) in linear time: `sebp`'s attachment compares
every rectangle on a plane with every opposite one, 8 s for 8,700 blocks; the bucketed version takes 0.5 s for 10,000. `HullResult.validate()` uses it; the demo also runs sebp's own `validate()`.

Measured (this machine, `python3 -I tools/hull_demo.py --bench 10000`; solid 10,177-cell ellipsoid hull with bow zone, 10,177 large-grid blocks):
volume build 0.03 s, mapping 0.27 s, mount check 0.02 s, fast validate 0.53 s, report 0.04 s, XML 0.20 s: about 1.1 s end to end. The two demo ships (~1,000 and ~1,400 blocks) build in 0.1 s and 0.4 s.

Both pass `res.check()` and `sebp.Blueprint.validate()` (one connected piece, no overlaps, every block attached, no DLC). The renders (`fighter.png`, `frigate.png`: four yaw views through `sebp.Blueprint.thumb`; `*_ortho.png`: top/side/front silhouettes) go to `--out`.
The demo hulls are demonstrations, not the ships of the warship plan; masses are armour-heavy because every wall is a full block.

## 9. Not covered / known limits

- **Nothing here was seen in the game.** Orientation comes from the mount points (as the catalogue says), not from the model mesh; whether a `Slope2Tip` looks right in the game, and
  where the glass of `Window1x1Flat`/`Window1x1Slope` sits inside its cell (the mapper treats the window's full-mount face as the face against the hull), needs an in-game paste of the demo hulls.
- Shape set: Block, Slope, Corner, CornerInv, Slope2Base/Tip, Round variants, `Window1x1Slope/Flat`, `ArmorPanel`, `HalfArmorBlock` slabs. Not used: Corner2/InvCorner2, SquareSloped, Transition,
  HalfCorner families (the 2:1 ramp is only detected for a straight staircase; diagonal ramps fall back to 1:1 slopes and corners), knife edges stay cubes.
- Fillets seat only on plain cubes and only in 90-degree concave edges and vertices.
- Multi-cell blocks (windows 1x2, 3x3) and sloped-corner windows are not emitted; `check_mount_faces` only examines 1x1x1 CubeBlocks.
- Hardpoints need flat, cube-shaped hull; the cell-count of a footprint is not limited by the turret's real size, the designer passes `footprint`/`height`.
- Thumbnails (`sebp.thumb`) draw every block as a full cube, so slopes look like stairs; the real hull is smoother.
- `hollow()` makes skins from the voxel solid; very thin features (1-cell fins) are all skin and need no partitions. Heavy walls make the demo ships very heavy; use `heavy_depth` or light zones to trade mass for HP.
